运维自动化脚本工具箱：8 个高频场景脚本

2026-08-13 · 冯 · 项目：OpsToolkit

运维工作中，很多重复劳动都值得用脚本自动化。我把最常遇到的场景整理成了一个工具箱 OpsToolkit， 全部基于 Python 标准库 / Shell 实现，拷到服务器上就能跑，不用装任何依赖。

脚本清单与使用场景

脚本解决的痛点
log_rotate.py日志文件无限增长撑爆磁盘
backup.py数据没有定期备份、误删无法恢复
health_check.py批量探活多台服务的端口 / HTTP 状态
disk_cleanup.py临时文件堆积、找不到大文件占空间
process_guard.py服务进程崩溃后无人拉起
deploy.py每次发版手动 git pull + 重启容易出错
batch_ssh.sh逐台登录多台主机执行命令太慢
check_disk_space.sh磁盘快满了却不知道，直到服务挂掉

设计要点

1. 每个脚本只做一件事

遵循 Unix 哲学，脚本通过 argparse 参数化，而不是写死路径。这样可以用管道、cron、systemd timer 任意组合。

2. 幂等与安全

轮转、清理这类「删文件」的操作，都带 --dry-run 预演模式，先看清楚要删什么再真正执行：

python3 log_rotate.py --dir /var/log/myapp --max-size 50 --keep 7 --dry-run

3. 可观测

所有脚本统一输出到 stdout，带上时间戳和明确的状态标记（[backup]、[del]、[ALERT]）， 便于重定向到日志文件或接入集中日志平台。

一个例子：日志轮转

日志轮转的核心是「移位 + 压缩 + 清理」，本质是维护一个最多 keep 份的环形队列：

app.log.3 删除          # 最旧的先删
app.log.2 → app.log.3   # 从旧到新依次后移
app.log.1 → app.log.2
app.log   → app.log.1   # 当前日志归档
# 最后 gzip 压缩 app.log.1，并 touch 一个空 app.log 供程序继续写

小结

把高频操作脚本化，是运维「自动化」的第一步。这些脚本也可以作为面试时的谈资—— 展示你如何用工程化的方式解决重复劳动，而不是「每次手动敲命令」。

完整代码见 github.com/sakura44u/ops-toolkit。
