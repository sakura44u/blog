Docker 多阶段构建 + GitHub Actions 实现自动化部署

2026-08-16 · 冯 · 项目：DevOps-CICD

「部署」是运维最基础也最容易出错的工作。手动 git pull、重启服务、改配置，稍有不慎就会带病上线。 这篇文章用我的 DevOps-CICD 项目，串起一条完整的自动化链路： 代码推送 → 自动测试 → 构建镜像 → 推送仓库 → 自动部署。

1. Docker 多阶段构建

多阶段构建的核心思想：构建环境与运行环境分离。第一阶段装依赖，第二阶段只复制产物：

# 阶段一：安装依赖
FROM python:3.11-slim AS builder
COPY requirements.txt .
RUN pip install --user -r requirements.txt

# 阶段二：只带运行时依赖 + 代码，镜像更小更安全
FROM python:3.11-slim
COPY --from=builder /root/.local /root/.local
COPY app ./app
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]

这样最终镜像里没有编译器、没有 requirements.txt 之外的多余文件，体积和攻击面都更小。

2. 编排与健康检查

docker-compose.yml 里给服务配了 healthcheck，让编排系统能自动感知服务是否健康：

healthcheck:
  test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health')"]
  interval: 30s
  timeout: 5s
  retries: 3

Nginx 作为反向代理统一入口，后端服务只暴露内网端口，隐藏实现细节。

3. CI：每次提交自动测试

.github/workflows/ci.yml 在每次 push / PR 时自动安装依赖并跑测试，避免坏代码进主干：

on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
      - run: pip install -r requirements.txt -r requirements-dev.txt
      - run: pytest -v

4. CD：构建镜像并部署

deploy.yml 在合并到 main 后，构建镜像推送到 GitHub Container Registry，再通过 SSH 到服务器执行部署：

jobs:
  build-push:
    steps:
      - uses: docker/login-action@v3        # 登录 GHCR
      - uses: docker/build-push-action@v5    # 构建并推送镜像
  deploy:
    needs: build-push
    steps:
      - uses: appleboy/ssh-action@v1.0.3     # SSH 到服务器
        with:
          script: docker compose pull && docker compose up -d

服务器信息通过仓库的 Secrets（DEPLOY_HOST / DEPLOY_USER / DEPLOY_KEY）配置，不硬编码在仓库里。

小结

这套流水线把「重复、易错」的部署动作变成了「提交代码即上线」，是 DevOps 理念最直观的落地。 理解了它，再接触 Jenkins / GitLab CI / ArgoCD 就能快速上手。
