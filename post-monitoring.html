从零搭建一个系统监控与告警平台

2026-08-10 · 冯 · 项目：OpsMonitor

对一名运维工程师来说，监控与告警是最核心的能力之一。与其直接上手 Prometheus + Grafana 这样的重型方案， 不如先用几百行代码自己实现一个轻量监控系统，把原理吃透。这篇文章记录我用 Python + FastAPI + psutil 从零搭建 OpsMonitor 的过程。

整体架构

系统分三层，职责清晰：

采集层 collector.py  ──►  存储层 storage.py  ──►  展示层 api.py + web/
        │                        │
        └── psutil 周期采集        └── SQLite 持久化 + 阈值检测(alerter.py)

1. 指标采集：psutil

psutil 是一个跨平台的系统监控库，几行代码就能拿到 CPU、内存、磁盘、网络等信息：

import psutil

cpu = psutil.cpu_percent(interval=0.5)      # CPU 使用率
mem = psutil.virtual_memory()               # 内存：.percent .used .total
disk = {p.mountpoint: psutil.disk_usage(p.mountpoint).percent
        for p in psutil.disk_partitions()}  # 各分区磁盘使用率
net = psutil.net_io_counters()              # 网络收发字节数

采集逻辑放在一个后台线程里，用 threading.Event 控制周期，异常不会中断主进程。

2. 存储：SQLite

指标数据用 SQLite 落地（Python 标准库自带，无需额外部署）。关键点是幂等写入 + 定期清理：

INSERT OR REPLACE INTO metrics VALUES(...)   -- 以时间戳为主键，重复采集不产生脏数据
DELETE FROM metrics WHERE ts < ?             -- 每次写入顺带清理超过保留时长的旧数据

3. 告警：阈值检测 + 冷却去重

告警最怕「刷屏」——同一个问题每 5 秒发一条，几百条消息瞬间淹没群。解决思路是冷却去重：

# 同一告警消息在 cooldown 秒内只发一次
if message in self._last_alert and now - self._last_alert[message] < cooldown:
    return
self._last_alert[message] = now

通知渠道做了两层抽象：SMTP 邮件 + 通用 Webhook（钉钉 / 企业微信 / 飞书机器人都兼容）。

4. 展示：FastAPI + Chart.js

FastAPI 同时提供 REST API 和静态仪表盘，前端每 5 秒拉一次数据渲染趋势图：

GET /api/health                 # 健康检查
GET /api/metrics/current        # 最新指标
GET /api/metrics/history?limit  # 历史趋势
GET /api/alerts                 # 告警记录

小结

这套系统虽然轻量，但完整覆盖了监控的「采集 → 存储 → 告警 → 展示」闭环。理解了它，再去学 Prometheus 的 exporter / 时序库 / alertmanager 就顺理成章了。

完整代码见 github.com/sakura44u/ops-monitor。
